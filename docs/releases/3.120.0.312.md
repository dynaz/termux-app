# TermiNow 3.120.0.312 — Internal

รุ่นทดสอบภายใน (Internal testing) · ไม่ใช่รุ่น production · 2 พ.ย. 2026 · arm64-v8a เท่านั้น

รุ่นนี้รวมงานใหม่บนสาขา `backup-schedule-cloud` เพื่อทดสอบบนอุปกรณ์และเครือข่าย/เซิร์ฟเวอร์จริง ก่อนพิจารณาปล่อยจริง (production ปัจจุบันคือ 304)

## ใหม่

- **Network Discovery (ออกแบบใหม่):** เพิ่มการสแกนด้วย ICMP (ping) ควบคู่กับการสแกนพอร์ต TCP จึงพบอุปกรณ์ที่ตอบ ping แม้ไม่มีพอร์ตเปิด; การ์ดอุปกรณ์มีไอคอนประเภท (เกตเวย์ / เครื่องพิมพ์ / NAS / เซิร์ฟเวอร์ / เว็บ / เดสก์ท็อป) ที่ "คาดเดา" จากพอร์ต+ชื่อโฮสต์; หน้ารายละเอียดอุปกรณ์แสดงชื่อ/ประเภท/IP/ผู้ผลิต + พอร์ตที่เปิดพร้อมชื่อบริการ (เปิด http/https ในเบราว์เซอร์ได้) + ปุ่มเชื่อมต่อ SSH / บันทึกเป็น Host / คัดลอก IP (ใช้การเชื่อมต่อเดิมที่มีอยู่)
- **Local Linux (ออกแบบใหม่):** สวิตช์ **"Use tmux" ต่อ distro** (จำค่าแยกแต่ละ distro, มีผลเฉพาะ session ใหม่, มีปุ่มข้อมูลอธิบายข้อจำกัดเรื่องการคงอยู่ของ session), ตัวเลือก **"Select OS"** แบบการ์ดพร้อมโลโก้/เวอร์ชัน/ระดับสิทธิ์/จำนวนที่กำลังรัน/ช่องค้นหา (เลือกแล้วสลับตัวจัดการ ไม่เปิดเทอร์มินัลทันที), และ **ส่วนจัดการ tmux session** (attach / เปลี่ยนชื่อ / detach / kill พร้อมยืนยัน) ในตัวจัดการ session; ซ่อนแป้นพิมพ์ก่อนเปิดแผง
- **เครื่องมือความปลอดภัย + จับแพ็กเก็ต (Kali/Linux):** ติดตั้งเครื่องมือทีละตัวผ่าน apt (ไม่ใช้ metapackage), จับแพ็กเก็ตด้วย tcpdump/tshark แบบมีขอบเขต, และจับแพ็กเก็ตบนโฮสต์ระยะไกลผ่าน SSH
- **ตัวดู VNC ในตัว:** ไคลเอนต์ RFB ภาษา Java ล้วน เปิดดูหน้าจอ VNC ได้ในแอป
- **สำรอง/กู้คืน (คลาวด์ + ตั้งเวลา):** เข้ารหัสไฟล์สำรอง, อัปโหลด S3, และตั้งเวลา/นโยบายการเก็บรักษา

## สถานะการตรวจสอบ

- **ตรวจแล้ว (ระดับ build):** คอมไพล์ผ่านทั้งสอง flavor; unit tests ที่เกี่ยวข้องผ่าน (Network Discovery/scanner 29, VNC 11, Backup 19, security + capture ฯลฯ); ไลบรารีเนทีฟ arm64-v8a ครบทั้ง 4 (libtermux, libtermux-bootstrap, libproot-loader, libterminow-rdp); เซ็นด้วย upload key; Play ยอมรับ bundle และปล่อยบน internal track แล้ว
- **ยังไม่ได้ตรวจบนอุปกรณ์จริง:** UI และพฤติกรรมจริงทั้งหมดข้างต้น (บิลด์บน proot aarch64 ไม่มีอุปกรณ์จริง) โดยเฉพาะ: สวิตช์ Use tmux / Select OS / การจัดการ tmux session, หน้ารายละเอียด Network Discovery บนเครือข่ายจริง, การติดตั้งเครื่องมือความปลอดภัยและการจับแพ็กเก็ต (ในเครื่องและระยะไกล), และตัวดู VNC กับเซิร์ฟเวอร์จริง
- **ข้อจำกัดของ Android (Network Discovery):** ไม่มี raw ICMP หากไม่มี root (`isReachable` fallback เป็น TCP:7 — ping ที่ล้มเหลว "ไม่สรุปว่าออฟไลน์"); อ่าน MAC/ผู้ผลิตของเพื่อนบ้านไม่ได้ (ARP `/proc/net/arp` ถูกบล็อกตั้งแต่ API 29) จึงแสดง "Unknown" ไม่กุขึ้นเอง; เกตเวย์อ่านแบบ best-effort จาก `/proc/net/route`; ประเภท/บริการเป็นการ "คาดเดา"
- arm64-v8a เท่านั้น (ยังไม่รวม x86_64 ในบิลด์นี้)

## หมายเหตุด้านความปลอดภัย

- เครื่องมือความปลอดภัยมีไว้สำหรับการทดสอบที่ได้รับอนุญาตเท่านั้น; ไม่อัปโหลดเนื้อหาที่จับได้ไปยัง AI/บุคคลที่สามโดยอัตโนมัติ
- การจับแพ็กเก็ตระยะไกล: ไม่ติดตั้งแพ็กเกจหรือแก้สิทธิ์บนโฮสต์โดยอัตโนมัติ, เก็บไฟล์ที่จับไว้บนโฮสต์จนกว่าจะดาวน์โหลดสำเร็จ, ติดตามเฉพาะโพรเซสที่งานจับนี้สร้าง
- VNC: ไม่บันทึกรหัสผ่านลง log, ใช้ที่เก็บข้อมูลลับที่เข้ารหัสเดิม
- การ Disconnect/stop จัดการเฉพาะ session นั้น ไม่ปิด SSH/SFTP หรือ session อื่นของ Ubuntu
